P-05 принимает доступную страницу и фиксирует ограничения; полная приемка требований возможна после реализации подтвержденных состояний. Кнопка, моки, загрузчик, токены и секции — внутренние пункты этапов, без отдельных исполнителей/приемок компонентов. Главный агент отвечает за итог этапа.

## Проверки и приемка

| Этап | Необходимые проверки / требования SPEC |
| --- | --- |
| P-02 | Реальные context и референсы, соответствие ассетов узлам и файлам, форматы/SHA-256, шрифты и значения стилей, полнота вариантов. Неизвестное явно отмечено; недостающие обязательные материалы не подменяются догадками. |
| P-03 | **R-01, R-06, R-07, R-09; основа R-02.** Build/types; все секции и тексты по Figma 375/1440; `src/app/components/button/`; стили через переменные. Корректный/неверный JSON, стабильные id и пути ассетов. Замена опубликованного JSON и перезагрузка меняют контент без пересборки JS. |
| P-04 | **R-03, R-04, R-05, R-08.** Цикл минимум трех hero-вариантов без скачка высоты; непрерывная строка; начало/середина/финал перекрытия призов, включая mobile и низкий viewport. Hover/focus-visible/active и touch; нет переходов, отправки форм, игровых и других бизнес-запросов. Reduced-motion, пауза в скрытой вкладке, очистка таймера. |
| P-05 | **Полная проверка R-01…R-09.** Ширины 320, 375, 390, 430, 768, 1024, 1280, 1440, 1920, 2560, 3840, 7680; обе ориентации tablet, высокий DPR и низкий viewport. Нет случайного overflow/обрезания текста. Сверка с Figma, клавиатура, семантика/alt/фокус, runtime JSON и все эффекты. Production build, доступные typecheck/lint, просмотр diff и актуальные документы. Эмуляцию 8К отличать от проверки на реальном устройстве. |

Главный агент проверяет каждый вклад субагента и интегрированный результат. Пользователь получает **одну ручную приемку законченного этапа**, включающую результаты задействованных субагентов; отдельной приемки кнопки или каждой секции нет. Финальная приемка проверяет всю страницу.

Статусы: `запланировано` → `в работе` → `проверка главным агентом` → `ожидает ручной проверки` → `готово`. Для замечаний — `на доработке`, для внешнего ограничения — `заблокировано` с причиной. Отчет исполнителя и коммит не заменяют приемку. По мере работы обновлять статус этапа и доказательства проверки.

Новые автотесты сначала предложить пользователю с объяснением назначения, согласно AGENTS.md; критический функционал должен быть покрыт тестами. Подходящие существующие проверки запускаются без создания отдельных этапов тестирования для компонентов. Для текущего приложения настроены build и typecheck; отдельный lint не настроен. Новые тестовые файлы не создавались.
