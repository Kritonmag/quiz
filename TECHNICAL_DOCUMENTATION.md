# Техническая документация Quiz

Актуально на 14.10.2026. Документ описывает текущую реализацию демонстрационной страницы «Железные факты» по исходному коду, локальным данным и сохраненным отчетам проверки. Новая браузерная проверка не проводилась: сохраняется согласованное ограничение доступа. Требования проекта находятся в [SPEC.md](SPEC.md), решения — в [ARCHITECTURE.md](ARCHITECTURE.md), статус приемки — в [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md).

## Назначение и возможности

Одностраничное приложение знакомит с проектом о профессиях РЖД, показывает примеры вопросов, призы, рейтинг и описание механики игры. Реализованы локальные демонстрационные эффекты. Серверной части, авторизации, игровой сессии, проверки ответов, начисления баллов и выдачи призов нет.

| Раздел | Что отображается и происходит |
| --- | --- |
| Header | Логотип, меню, CTA и мобильная кнопка меню. Обычный клик по ссылкам отменяется; мобильное меню не раскрывается. |
| Hero | Заголовок, три вопроса с фотографиями, «Да/Нет», CTA и бегущая строка. Обе кнопки ответа переключают следующий вопрос. |
| Призы | Три текстовых правила, три карточки и CTA. При прокрутке нижние карточки перекрывают верхние. |
| Рейтинг | Топ-3 и места 4–10 из JSON. Данные не рассчитываются и не сортируются приложением. «Все результаты» имеет только визуальные состояния. |
| Механика | Три пункта: 10 раундов, 10 вопросов, 100 фактов. Это описание предполагаемой игры. |
| Финальный CTA | Призыв к участию, фотография и декоративная графика. |
| Footer | Описание, организатор, поддержка, юридические и социальные ссылки. Обычные переходы по клику отменяются. |

Общий CTA-компонент использует нативный `button` с `type="button"`, подписью и красным/белым вариантом оформления. Бизнес-обработчиков у CTA нет. Hover, focus-visible и active задаются CSS.

## Стек и запуск

Angular 20.3.17, Angular CLI/build 20.3.19, TypeScript 5.9.3, RxJS 7.8.2. Компоненты standalone; включено zoneless-обновление через Angular signals. Router, UI-библиотека и отдельное хранилище состояния не используются.

Проверенное окружение: Node.js 22.15.0 и npm 10.9.2. Для воспроизводимого запуска используйте Node.js 22 LTS версии 22.12 или новее в этой ветке и существующий lock-файл.

```sh
npm ci
npm start
```

Адрес локального сервера: `http://localhost:4222/`. Порт задан в [package.json](package.json). Dev server использует production-конфигурацию сборки.

```sh
npm run typecheck
npm run build
```

`typecheck` проверяет TypeScript, production build также компилирует Angular-шаблоны. Результат сборки — `dist/quiz-demo/browser/`. Отдельные команды lint и test не настроены. Настройки сборки: [angular.json](angular.json); начальный JS/CSS-бюджет — предупреждение после 1 MB, ошибка после 2 MB.

## Структура исходников

```text
src/
  main.ts                         # bootstrap, HttpClient, zoneless
  index.html
  styles.css                      # общие стили и контейнер
  styles/tokens.css               # переменные оформления
  app/
    app.component.ts/html/css     # загрузка и сборка страницы
    components/button/            # переиспользуемый CTA
    quiz/
      quiz-content.ts             # типы и runtime-валидация
      quiz-content.service.ts     # HTTP-загрузка JSON
      header/
      hero/
      prizes/
      leaderboard/
      mechanics/
      final-cta/
      footer/
public/
  mocks/quiz.json                  # редактируемые данные
  assets/figma/                    # сохраненные экспорты Figma
  assets/hero-user/                # фотографии Q2 и Q3 пользователя
docs/                             # материалы макета, задания и проверки
```

Обозначение `ts/html/css` в дереве означает три отдельных файла. Каждый из семи разделов и общая кнопка имеют собственную папку с `.component.ts`, `.component.html`, `.component.css`. В TS находятся inputs и поведение, в HTML — разметка, в CSS — оформление компонента. Используется стандартная изоляция стилей Angular; глобальными остаются общие правила и CSS-переменные.

## Загрузка и состояние

1. [main.ts](src/main.ts) запускает `AppComponent` и подключает `HttpClient`.
2. [AppComponent](src/app/app.component.ts) при инициализации вызывает `QuizContentService.load()`.
3. [Сервис](src/app/quiz/quiz-content.service.ts) делает GET по относительному адресу `mocks/quiz.json` и проверяет ответ через `isQuizContent`.
4. Валидный объект передается разделам через обязательный input `data`. Пока ответ не получен, отображается состояние загрузки.
5. Ошибка HTTP, разбора JSON или структуры данных переключает страницу в техническое сообщение об ошибке. Автоматического повторного запроса нет; после исправления требуется перезагрузка.

Контент загружается один раз при открытии страницы. Опрос сервера и сохранение состояния между перезагрузками отсутствуют. Индекс hero-вопроса хранится локально в компоненте и начинается с нуля. Технические тексты загрузки/ошибки находятся в шаблоне приложения.

## Управление контентом

Источник: [public/mocks/quiz.json](public/mocks/quiz.json). Точный контракт и проверка: [quiz-content.ts](src/app/quiz/quiz-content.ts).

| Ключ JSON | Содержимое |
| --- | --- |
| `header` | Подписи бренда, меню с `id`, `label`, `href`, текст CTA |
| `hero` | Заголовки, описание, `questions`, текст строки, `ribbonSpeedPxPerSecond`, CTA |
| `prizes` | Заголовки, вводный текст, `rules`, `cards`, параметры `sticky`, CTA |
| `leaderboard` | Заголовки, массивы `top` и `other`, подпись CTA |
| `mechanics` | Заголовки и `items` с числом, подписью и описанием |
| `finalCta` | Части заголовка, описание, CTA, alt фотографии |
| `footer` | Тексты, контакты, юридические ссылки, социальные ссылки и иконки, copyright |

Валидатор требует все семь разделов, непустые обязательные строки и уникальные `id` внутри каждого проверяемого массива. Hero содержит ровно 3 вопроса, призы — 3 правила и 3 карточки, рейтинг — 3 лидера и 7 остальных игроков, механика — 3 пункта, footer — 3 юридические и 2 социальные ссылки. Меню должно быть непустым.

У вопроса обязательны `id`, `text`, `yes`, `no`, `image`, `imageAlt`. Изображение и alt либо заданы вместе, либо оба равны `null`; второй вариант включает карточку без фотографии. Сейчас фотографии есть у всех трех вопросов.

Пути управляемых изображений начинаются с `assets/figma/` или `assets/hero-user/`, не содержат `..` и имеют расширение PNG, JPG/JPEG, WebP или SVG. Runtime-валидация проверяет строку пути, но не существование файла. Отсутствующий файл изображения не превращает валидный JSON в ошибку загрузки всей страницы.

Сохраняйте текущие структурные идентификаторы: `q1/q2/q3`, `main`, `rank-1/rank-2` используются шаблонами для вариантов оформления. Изменение количества элементов требует изменения контракта и проверки верстки. Значения `href` хранятся в данных, но их редактирование не включает навигацию.

Не вся графика управляется JSON: логотип, фоновые SVG, декоративные элементы и путь фотографии финального CTA закреплены в HTML/CSS. Для их замены по новому пути нужна правка исходников и сборка. Тексты и доступные описания основных блоков вынесены в JSON.

### Изменение без пересборки

При разработке измените `public/mocks/quiz.json` и перезагрузите страницу. На опубликованном сайте замените именно размещенный `mocks/quiz.json`; изменение исходного `public/` само по себе не обновляет уже опубликованную сборку.

Для новой фотографии разместите файл в соответствующей папке `assets/`, затем обновите путь и alt в JSON. После правки проверьте загрузку, отображение текста и фотографий. Если хостинг или CDN кеширует JSON, обеспечьте его обновление/ревалидацию настройками хостинга. Собственных серверных правил кеширования в репозитории нет.

## Эффекты

### Hero-карточки

[HeroComponent](src/app/quiz/hero/hero.component.ts) хранит `questionIndex` в signal, а `currentQuestion` вычисляет из данных. Нажатие любой кнопки ответа вызывает `nextQuestion()` и меняет индекс по модулю длины массива: Q1 → Q2 → Q3 → Q1. Одновременно обновляются вопрос, изображение и alt. Правильность ответа не оценивается, запросов и баллов нет; автоматического таймера смены нет. Текст вопроса имеет `aria-live="polite"`.

### Бегущая строка

CSS-анимация перемещает две одинаковые группы фраз. Число повторов и длительность рассчитываются по измеренной ширине и скорости из JSON. `ResizeObserver` и обработчик resize обновляют расчет. Строка приостанавливается при скрытой вкладке и hover/focus внутри области hero-action. При `prefers-reduced-motion: reduce` вместо движения остается читаемая фраза. Декоративные повторы скрыты от скринридера. Observer и обработчики удаляются при уничтожении компонента.

### Перекрытие призов

[PrizesComponent](src/app/quiz/prizes/prizes.component.ts) использует CSS `position: sticky` и порядок слоев карточек. Верхние отступы рассчитываются по настройкам, высоте viewport и измеренным высотам карточек. На низком экране допускаются отрицательные sticky-отступы, чтобы высокая карточка могла прокручиваться. Изменения размеров и ориентации запускают пересчет; обработчики и observer очищаются при уничтожении.

| Параметр JSON | Текущее значение | Допустимый диапазон |
| --- | --- | --- |
| `hero.ribbonSpeedPxPerSecond` | 48 px/s | 10–300 |
| `prizes.sticky.desktopTopPx` | 80 px | 0–300 |
| `prizes.sticky.desktopStepPx` | 70 px | 1–150 |
| `prizes.sticky.mobileTopPx` | 16 px | 0–100 |
| `prizes.sticky.mobileStepPx` | 48 px | 1–100 |
| `prizes.sticky.bottomGapPx` | 16 px | 0–100 |
| `prizes.sticky.runwayPx` | 260 px | 100–2000 |

Desktop-параметры sticky используются от 769 CSS px. Скорость и алгоритм адаптации — инженерные решения реализации; точная анимация Figma не подтверждена полным motion-контекстом.

## Оформление и адаптивность

Повторяющиеся значения вынесены в [tokens.css](src/styles/tokens.css): цвета, интервалы, размеры, типографика, длительности и слои. Секционные media queries находятся рядом с компонентами. Основные границы — 1200 и 768 px, отдельные корректировки — до 374 px. Контент ограничивается контейнером, фоны заполняют ширину; пропорционального увеличения интерфейса до 8К нет.

Исходные референсы Figma: desktop 1440 px и mobile 375 px. Остальные размеры и поведение на 8К требуют проверки, а не считаются подтвержденными макетом. Временно используется согласованный Arial: оригинальные RussianRail/FSRAIL отсутствуют.

В разметке предусмотрены header/main/section/footer, h1/h2/h3, alt для содержательных изображений и скрытие декоративной графики. Кнопки поддерживают клавиатурный фокус; reduced-motion уменьшает анимации. Эти механизмы присутствуют в коде, но не заменяют ручную проверку доступности.

## Публикация и диагностика

После `npm run build` разместите содержимое `dist/quiz-demo/browser/` на статическом HTTP-хостинге, включая `assets/` и `mocks/`. В исходном `index.html` нет тега base, URL ресурсов относительные. При публикации в подпапке проверьте адрес страницы с завершающим `/` и разрешение относительных URL; при необходимости явно настройте base href при сборке. Приложение не предназначено для запуска двойным кликом по `index.html`: контент загружается HTTP-запросом.

При сообщении об ошибке страницы проверьте ответ GET `mocks/quiz.json`, синтаксис JSON и контракт. При отсутствующем изображении проверьте путь, регистр имени и наличие файла на хостинге. При старом контенте проверьте опубликованный JSON и кеш. Повторная загрузка страницы сбрасывает выбранный вопрос на Q1.

При подготовке этого документа исходники приложения не менялись. Сверены команды, схема данных, обработчики и пути документации. Build повторно только ради Markdown не запускался.

Единая ручная приемка P-05 остается открытой:

1. Проверить загрузку страницы и три переключения «Да/Нет» с соответствующими фотографиями.
2. Проверить бегущую строку, паузу при фокусе/скрытии вкладки и reduced-motion.
3. Прокрутить призы от начала до конца, включая низкий viewport; весь текст должен быть доступен.
4. Проверить Tab, фокус, hover/active и отсутствие реальных действий CTA.
5. Проверить замену опубликованного JSON и состояние ошибки на отдельной проверочной копии.
6. Проверить ширины 320, 375, 390, 430, 768, 1024, 1280, 1440, 1920, 2560, 3840 и 7680 CSS px, обе ориентации планшета и высокий DPR. Сверить 375/1440 с сохраненными референсами. Эмуляцию 8К отличать от проверки физического монитора.

Принятые пользователем P-03/P-04 и наличие успешной сборки не закрывают ограничения P-02 и финальную визуальную приемку P-05.
