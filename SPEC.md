# Спецификация страницы Quiz

Версия: 1.0. Дата: 2026-10-14. Основание: PROMPT-002, PROMPT-003, PROMPT-005, PROMPT-006, PROMPT-008, PROMPT-010…PROMPT-018 в `prompts.md`. Требования R-01…R-09 сохранены; доступные части реализуются с явными ограничениями.

## Цель и границы

Создать адаптивную демонстрационную страницу «Железные факты» на **Angular 20+** по [макету Quiz](https://www.figma.com/design/0unNm6ej8Ig8v7eN5wUpZK/Quiz--Copy-?node-id=1-266).

Страница демонстрирует оформление и визуальное поведение. Кнопки не запускают реальную игру, не отправляют формы, не выполняют оплату, авторизацию, выдачу призов или внешние переходы. Результаты и тексты правил игры показываются из мок-данных; расчет результатов игры не входит в задачу.

По PROMPT-005 мок-данные всего проекта размещаются в отдельной папке `public/mocks/`. По упрощенному плану PROMPT-010 подготовка данных всех секций, загрузка и интеграция входят в этап P-03 «Готовая адаптивная страница», без самостоятельной приемки каждой технической части. Начальный файл — `public/mocks/quiz.json`, URL во время работы страницы — `mocks/quiz.json`.

## Требования и приемка

| ID | Требование | Критерий приемки |
| --- | --- | --- |
| R-01 | Angular 20+ | Версия зафиксирована в package.json и lock-файле; production build проходит |
| R-02 | Адаптивность: 8К, desktop, tablet, mobile | Проверены ширины из матрицы ниже; нет горизонтального скролла, обрезанного текста и случайных перекрытий |
| R-03 | Карточки hero меняются в динамике | Каждое нажатие Да/Нет переключает следующий вариант, Q1 → Q2 → Q3 → Q1; текст и соответствующий портрет меняются вместе, контент в JSON, высота блока стабильна. PNG Q2/Q3 предоставлены пользователем по PROMPT-018 |
| R-04 | «Подарок уже через 10 вопросов» — бегущая строка | Фраза движется непрерывно и зацикливается без видимого скачка; вспомогательные дубликаты скрыты от скринридера |
| R-05 | В «Что можно получить» нижняя карточка перекрывает верхнюю при скролле | Проверены начало, промежуточное и финальное состояния, порядок слоев; финал сверяется с `1:2104`; весь текст доступен для чтения |
| R-06 | Контент меняется без пересборки фронта | Меню, тексты, hero-варианты, призы, рейтинг, результаты, ссылки, подписи, контакты, доступные описания и параметры смены карточек загружаются из внешнего JSON во время работы страницы; замена опубликованного JSON и перезагрузка меняют страницу без сборки JS |
| R-07 | Повторяющиеся стили вынесены в переменные | Цвета, интервалы, радиусы, типографика, ширины контейнеров, длительности и порядок слоев используют именованные CSS custom properties |
| R-08 | Все кнопки имеют визуальный интерактив без реальных действий | Есть hover для мыши, focus-visible для клавиатуры и active для нажатия; клик не вызывает бизнес-запросы, переходы или отправку формы |
| R-09 | Общая папка компонентов и переиспользуемая кнопка | Есть `src/app/components/button/`; повторяющиеся CTA используют один компонент кнопки с общими состояниями и вариантами; новые общие компоненты можно добавлять в эту папку по необходимости |

### Состав страницы

1. Header: логотип, меню, демонстрационная кнопка; мобильное состояние меню есть в Figma (`1:1540`).
2. Hero (`1:1589`): название, описание, динамические карточки, CTA, бегущая строка.
3. Призы / «Что можно получить» (`1:1611`): описание, текстовые правила начисления баллов, три перекрывающиеся карточки, CTA.
4. Рейтинг (`1:1940`): топ-3, места 4–10, демонстрационная кнопка «Все результаты».
5. Механика игры (`1:2044`): 10 раундов, 10 вопросов, 100 фактов; это контент, а не реализация игры.
6. Финальный CTA и Footer (`1:2066`, Footer `1:2081`): название проекта, контакты, организатор, юридические ссылки.

### Матрица адаптивной проверки

| Группа | Ширины viewport в CSS px |
| --- | --- |
| Mobile | 320, **375**, 390, 430 |
| Tablet | 768, 1024; обе ориентации |
| Desktop | 1280, **1440**, 1920 |
| Большие экраны | 2560, 3840, **7680** |

На 375 и 1440 px сверять с соответствующим Figma-фреймом. Между ними сохранять порядок блоков и читаемость. Для широких экранов рабочее предложение: центрировать контент с ограниченной максимальной шириной, растягивать фоны. Не увеличивать шрифты и карточки пропорционально ширине 8К.

8К-монитор обычно использует масштабирование ОС: отдельно проверить CSS viewport 7680 × 4320 как крайний случай и обычный desktop viewport с повышенным DPR. Эмуляция не заменяет проверку на физическом устройстве; результаты фиксировать честно.

### Поведение и доступность

- Перекрытие призов обязательно при обычном скролле, включая mobile. Если высоты viewport не хватает, уменьшить sticky-ограничения так, чтобы весь контент можно было прочитать; не выключать эффект на всех мобильных ширинах без согласования.
- При `prefers-reduced-motion: reduce` остановить автосмену и бегущую строку, показать стабильную карточку и читаемую фразу. Уменьшить движение на hover. Это рабочее предложение по доступности.
- Не оставлять работающий таймер после уничтожения компонента; при скрытой вкладке приостанавливать ненужную смену карточек.
- Ошибку загрузки JSON показать как понятное состояние страницы с текстом из кода для технической ошибки. Не оставлять пустой экран или скрытый exception.
- Кнопки имеют `type="button"`. Ссылки демонстрируют визуальные состояния; настроенные URL хранятся в JSON, их реальный переход в демо отключен.
- Мобильное меню: рабочее предположение — разрешено только локальное открытие/закрытие как демонстрация интерфейса, без навигации. Если пользователь трактует запрет действий как запрет любых переключений UI, уточнить перед реализацией.
- Семантические header/main/section/footer, один h1, последовательные заголовки, alt и клавиатурный фокус. Декоративные дубликаты и графика не озвучиваются.

## До реализации необходимо уточнить или проверить

- Точную версию Angular 20+ и совместимость локального Node.js — при инициализации проекта, по официальной документации выбранной версии.
- Длительность и характер перехода hero: рабочее предложение — цикл каждые 4 секунды, переход 300 ms; финальные значения после просмотра прототипа/согласования.
- Ограничение ширины контента на 8К и точные точки перелома — после визуальной сверки; ширины тестирования не являются автоматически breakpoint-значениями.
- P-02 сохранил design context desktop/mobile/Final Scroll State, 350 ассетов и измеренные значения стилей. По PROMPT-011 доступная статическая верстка P-03 разрешена без полной приемки P-02 и без новых MCP-запросов. Только Q1, исходные призы, известные Default состояния; недостающие Q2/Q3, изображения, тексты и состояния не подменять придуманными.
- Подтверждены 6 сочетаний шрифта/начертания Figma, файлов и прав веб-использования нет. По PROMPT-012 временный Arial согласован для демонстрации P-03; это ограничение совпадения с Figma, не постоянная замена исходной типографики.
- В Footer есть `[юридическое наименование ЦПР]` и `[email]`: пока это исходные заглушки макета. Настоящие значения и URL не выдумывать.

Пользовательские требования R-01…R-09 обязательны. Рабочие предложения агента не считаются отдельной приемкой пользователя; изменения фиксируются в журнале решений.

По PROMPT-013 браузерная проверка текущего P-03 отменена пользователем после отказа шлюза. Требования адаптивности и визуальной сверки сохранены; их фактическое выполнение остается ручной проверкой/дальнейшей доводкой, а не подтвержденным результатом build.

По PROMPT-014 пользователь принял доступный статический P-03 с ограничениями и разрешил доступные эффекты P-04 тем же sol-6/high. По PROMPT-015 сначала сохранен коммит P-03 (daff15a). Для P-04 допустимы инженерные параметры строки/перекрытия и generic demo-интерактив; недостающие Q2/Q3, точные состояния и Motion не выдумываются. Все требования R-01…R-09 остаются в силе, неполная реализация перечисляется отдельно.

PROMPT-016 уточняет пользовательскую динамику hero: обе кнопки переключают демонстрационные карточки без оценки правильности/баллов и игровых запросов. Это разрешенное локальное изменение UI, совместимое с запретом бизнес-действий. Автотаймер не требуется этим уточнением. PROMPT-017 явно разрешает временно показывать Q2/Q3 без фотографий; тексты подтверждены новым пользовательским screenshot, вымышленные/подставные фото не допускаются.
