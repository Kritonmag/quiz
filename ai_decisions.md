# Решения AI

Журнал причин выбора и альтернатив. Не содержит скрытые рассуждения модели. Дата начальных записей: 2026-10-13. Автор: главный агент `/root`. Основание: PROMPT-003 и Figma MCP.

Требование пользователя и выбранное агентом рабочее решение имеют разные статусы. Начальная архитектура предложена и описана; пользователь еще не подтверждал отдельные предложения. При изменении добавлять новую запись со ссылкой на прежнюю, не стирать историю.

## D-01 — Стек и границы компонентов

**Статус:** Angular 20+ — задан пользователем; standalone-компоненты по разделам — выбраны для начальной архитектуры.

**Выбор:** одна страница, компоненты header/hero/prizes/leaderboard/mechanics/final-cta/footer, один сервис контента и локальное состояние.

**Почему:** разделы совпадают с макетом, независимы по поведению и понятны при ручной проверке. Для одной демонстрационной страницы общий state store и несколько архитектурных слоев не нужны. [Angular рекомендует standalone-компоненты для нового кода](https://angular.dev/guide/ngmodules/overview).

**Альтернативы:** один большой компонент проще начать, но смешивает анимации и все секции; NgModules добавляют лишнюю организацию; глобальный store и универсальный renderer секций усложняют текущую задачу. React не соответствует требованию Angular.

**Коррекции:** по PROMPT-006 добавлены общая папка `src/app/components/` и переиспользуемая кнопка; см. D-08. Правильность реализации еще не проверена.

## D-02 — Контент через runtime JSON

**Статус:** изменение контента без сборки — задано пользователем; один JSON и один сервис — рабочий выбор агента.

**Выбор:** `public/content/quiz.json`, загрузка HTTP во время работы приложения; на опубликованном сайте отдельно заменяется статический JSON. Простая проверка формы данных и явное состояние ошибки.

**Почему:** импорт JSON в TypeScript включает данные в сборку и не выполняет требование. Runtime-файл меняется независимо от JS. Для одного языка и одной страницы одного файла достаточно.

**Альтернативы:** отдельные JSON по секциям добавляют запросы и состояния; CMS/API потребуют инфраструктуры; TypeScript-константы потребуют пересборки. Возвращаться к CMS только при новом требовании.

**Ограничения:** изменение исходного `public/` не обновляет опубликованную сборку; нужен доступ к опубликованному файлу и корректное кеширование. Структура компонентов и дизайн остаются в коде.

**Коррекции:** по PROMPT-005 папка изменена на `public/mocks/`, подготовка мок-данных выделена в P-04A; см. D-07. Обновление без сборки предстоит доказать в P-04/P-09.

## D-03 — Анимации локально, CSS прежде всего

**Статус:** эффекты заданы пользователем; техника — рабочее предложение.

**Выбор:** CSS keyframes для строки, таймер и CSS-переход для hero, sticky и z-index для призов. Reduced-motion и очистка таймера.

**Почему:** это разные небольшие эффекты, общего движка им не требуется. CSS sticky позволяет перекрывать карточки без постоянных расчетов координат в JavaScript.

**Альтернативы:** библиотека анимаций добавляет production-зависимость и требует согласования; общий scroll engine преждевременен; ScrollTimeline можно рассмотреть только после проверки целевых браузеров. Если sticky не повторяет Figma, добавить локальный обработчик только в prizes.

**Ограничения:** параметры hero, высоты и offsets sticky пока не подтверждены визуально. Для низкого viewport нельзя прятать содержимое карточек.

**Коррекции:** пока нет; выбор техники еще требует проверки по `Final Scroll State`.

## D-04 — Адаптивность и 8К

**Статус:** поддержка устройств — обязательна; ограничение ширины на больших экранах — предложение.

**Выбор:** mobile-first, гибкая раскладка, центрированный контент с max-width, фоны на всю ширину.

**Почему:** MCP подтвердил desktop 1440 px и mobile 375 px. Секция 8147 px включает соседние варианты и компоненты. Растягивание страницы до ее ширины сделает текст и карточки несоразмерными.

**Альтернативы:** растяжение всех блоков на 7680 px ухудшает читаемость; масштабирование всего полотна transform ломает практическую раскладку; фиксированная страница 1440 px не работает на mobile.

**Коррекции:** пока нет. Точный max-width и точки перелома определяются в P-02/P-08, а не выдумываются из ширины полотна.

## D-05 — Разделение правил и журналов

**Статус:** документы запрошены пользователем; распределение ответственности выбрано агентом.

**Выбор:** AGENTS.md — точка входа; quiz.against.md — правила конкретного проекта; SPEC — требования; ARCHITECTURE — реализация; DEVELOPMENT_PLAN — статусы; prompts — исходные задания; ai_decisions — причины выбора; ai_noted — факты, замечания и коррекции.

**Почему:** агенты получают обязательный вход через AGENTS.md, а требования, предложения и фактические проверки не смешиваются. Журнал не должен выдавать предложение за уже принятый результат.

**Альтернативы:** один документ быстрее создать, но трудно поддерживать историю и актуальные статусы; переименование `quiz.against.md` могло бы нарушить явно запрошенное имя.

**Коррекции:** до появления проектного файла первый ответ содержал только «AGENTS.md учтен». После создания правила новая задача начинается с обоих подтверждений. Это настройка процесса, не исправление приложения.

**2026-10-13, PROMPT-004:** по уточнению пользователя `prompts.md` содержит только реестр, пользовательские промпты и шаблон. Задания агентов, порядок записи и служебные пояснения удалены; время, модель и степень рассуждения сохранены в реестре. Правила ведения журнала обновлены в `quiz.against.md`.

**13.10.2026, PROMPT-007:** пользователь уточнил модель и уровень рассуждения предыдущих записей: GPT-6.1 Solo, высокая степень. Время записи теперь отображается в формате `ДД.ММ.ГГГГ, ЧЧ:ММ:СС` по Москве. В правилах закреплены сообщения коммитов только на русском языке.

## D-06 — Приемка делегированной работы

**Статус:** задано пользователем.

**Выбор:** отчет субагента → проверка кода и подходящие проверки главным агентом → ручная проверка пользователем → готово. Статусы отражаются в плане, замечания — в ai_noted.

**Почему:** автоматическая проверка не подтверждает визуальную приемку, а отчет исполнителя не подтверждает интеграцию. Пользователь явно запросил собственную ручную проверку результатов субагентов.

**Альтернативы:** принимать по отчету субагента либо только по build — не выполняет запрос. Субагенты в этой задаче не запускались: сейчас подготовлена документация и порядок будущей работы.

**Коррекции:** пока нет; ручной приемки результатов субагентов еще не было.

## D-07 — Отдельная папка и исполнитель для мок-данных

**Статус:** отдельная папка и задача одного агента заданы пользователем в PROMPT-005; уточняет D-02.

**Выбор:** все мок-данные проекта размещаются в `public/mocks/`, начальный файл — `quiz.json`. Подготовка всех секций поручается одному субагенту в P-04A. Типы, загрузчик и интеграция остаются в P-04; ассеты — в `public/assets/`.

**Почему:** данные получают явную отдельную область и одного ответственного исполнителя; сохраняется обновление через HTTP без пересборки фронта. Задачу можно проверять независимо от верстки секций.

**Альтернативы:** прежний `public/content/` не отражает запрошенное выделение моков; размещение в `src/` с импортом привяжет данные к сборке; несколько JSON и сервер моков сейчас не нужны.

**Коррекция пользователя:** выделить мок-данные для всего проекта в отдельную папку и отдельную задачу агента. Архитектура, SPEC и зависимости плана обновлены. Данные еще не созданы, исполнитель не запущен; после проверки главным агентом требуется ручная приемка пользователя.

## D-08 — Общая папка компонентов и кнопка

**Статус:** задано пользователем в PROMPT-006; уточняет D-01 и прежнее предложение ограничиться общим CSS-классом кнопки до необходимости выделения компонента.

**Выбор:** `src/app/components/` для общих UI-компонентов, `button/` с ButtonComponent — первый компонент. Секции импортируют его для повторяющихся CTA; новые общие компоненты добавляются по потребности.

**Почему:** кнопка повторяется на всей странице. Один компонент сохраняет единые разметку, варианты и состояния и позволяет менять их во всем приложении в одном месте. Отдельная папка дает понятное место для будущего переиспользования.

**Альтернативы:** общий CSS-класс оставляет повторяющуюся разметку в секциях; копирование кнопки по разделам создает риск расхождений; базовые классы и универсальный UI-фреймворк не нужны.

**Коррекция пользователя:** сразу выделить общую кнопку и папку для будущих компонентов. Архитектура, SPEC, правила и план обновлены; реализация запланирована в P-04B. Компоненты секций остаются локальными, общая кнопка не содержит бизнес-логики.

## D-09 — Разбор P-02 и приемка при ограничении MCP

**Основание:** PROMPT-008, 14.10.2026. Один субагент `/root/figma_p02`, `gpt-6.1-sol`, reasoning `high`; приложение не инициализируется.

**Выбор:** исходные context, измерения и референсы — в `docs/figma/p02/`; доступные оригиналы — в `public/assets/figma/`. Главный агент владеет корневыми документами и `docs/reviews/`, сохраняет точное поручение отдельно в `docs/agent-tasks/` и независимо сверяет данные с MCP.

**Почему:** разделение исключает одновременные правки журналов, а независимый запрос и проверка всех файлов подтверждают результат фактическими данными. В манифесте различаются 371 объявления ресурсов, 350 уникальных файлов и 398 использований. Сотни мелких SVG — реальные экспортированные слои иллюстраций; их не объединяли и не перерисовывали.

**Альтернативы:** принять только отчет агента — недостаточно; подменить отсутствующие варианты догадками — не выполняет P-02; начать P-03 с неполными материалами — запрещено текущим запросом пользователя.

**Ограничение:** Starter quota не дает получить обязательные дополнительные context/PNG. Доступный пакет прошел проверку, но P-02 имеет статус `заблокировано`. После дозагрузки и повторной проверки главного агента необходима ручная приемка пользователя. Параметры 4000/300 ms, sticky, breakpoints и 8К max-width остаются предложениями; нулевые reactions у прямых детей не доказывают отсутствие вложенной motion.

**Уточнение фактов:** 14.10.2026 metadata фиксирует Homepage 8148 × 7417 вместо первоначальных 8147 × 7417; это не ширина страницы. Размеры desktop/mobile не изменились. Файлов и прав использования шрифтов пока нет.

## D-10 — План по законченным этапам демонстрационной страницы

**Основание:** PROMPT-010, 14.10.2026. Пользователь попросил сократить техническое дробление, сохранить ТЗ и проверки и предложить план перед продолжением.

**Предложение:** четыре этапа: P-02 — материалы Figma; P-03 — вся адаптивная страница с Angular, моками, загрузкой, токенами и общей кнопкой; P-04 — все демонстрационные эффекты; P-05 — доводка, итоговые проверки и передача. Один законченный результат и одна ручная приемка на этап; главный агент проверяет каждый вклад субагента внутри этапа.

**Почему:** кнопка, загрузчик и отдельная секция сами по себе не являются результатом всей демонстрационной страницы. Их интеграцию проще оценить вместе. Отдельные исполнители и приемки для каждого компонента добавляли процесс, не улучшая проверяемость результата.

**Альтернативы:** прежний подробный план из отдельных технических задач избыточен; один этап «сделать все» скроет промежуточную проверку и внешние ограничения. Четыре этапа сохраняют обозримые результаты и полноту R-01…R-09.

**Статус:** предложенная редакция сохранена в DEVELOPMENT_PLAN.md; разработка не продолжается. Папки моков и общих компонентов, простая архитектура и все требования сохранены. Исторические P-04A/P-04B включены в P-03, а самостоятельная приемка компонентов заменена приемкой этапов. P-02 по-прежнему заблокирована квотой, ее полнота и пользовательская приемка не заявляются.

## D-11 — Доступная реализация P-03 независимо от общей блокировки P-02

**Основание:** PROMPT-011 и PROMPT-012, 14.10.2026. Пользователь согласовал упрощенный план, старт P-03 по сохраненным данным и временный Arial.

**Выбор:** один субагент `/root/implementation_p03`, модель `gpt-6-sol` (запрошенный sol-6), reasoning `high`, реализует статическую страницу, моки и загрузку; главный агент ведет документы и независимо проверяет код, сборку и браузер. Никаких новых Figma MCP-запросов. Стандартный Angular 20 stack, без дополнительных UI/animation production-библиотек.

**Почему:** desktop/mobile context и локальные ассеты уже позволяют собрать известные секции и Q1. Общая блокировка P-02 не должна останавливать независимую работу. Недостающие Q2/Q3, точные состояния Button/Open menu и Motion остаются адресными зависимостями будущих функций P-04, а не разрешением их придумать.

**Шрифт:** оригинальные RussianRail/FSRAIL локально не найдены. Пользователь явно ответил «Разрешаю временный Arial». Используется честно именованный временный шрифт; точное совпадение метрик/начертаний и окончательная визуальная приемка шрифтов остаются ограничением.

**Альтернативы:** ждать полного P-02 — тормозит доступную работу; выдумать отсутствующий контент/hover — запрещено; скрыто назвать fallback оригинальным шрифтом — неверно. Анимации P-04 не запускаются внутри P-03.

**Совместимость:** установлен Node 22.15.0; [официальная таблица Angular](https://angular.dev/reference/versions) допускает Node ^22.12.0 и TypeScript >=5.8 <6 для Angular 20.3.x. Patch-версии фиксируются после проверки npm registry исполнителем.

## D-12 — Фактическая простая структура P-03

14.10.2026, P-03, PROMPT-011. Standalone-приложение и семь секций используют короткие inline-шаблоны, общий CSS и один переиспользуемый ButtonComponent. Отдельные app.config, quiz-page и подпапки для каждого короткого компонента из первоначального предложения не нужны: загрузка и три состояния страницы помещаются в корневом компоненте. Альтернатива — дополнительные файлы и слой страницы — увеличила бы объем без нового поведения. Архитектура синхронизирована с реализацией.

Angular 20.3 работает без zone.js через `provideZonelessChangeDetection()`; этот provider добавлен после независимого просмотра главного агента. Простая проверка JSON не требует библиотеки схем; публикуемый JSON остается отдельным ресурсом. Заданные id и три призовые/три podium позиции являются структурными; редактирование текста не требует их менять. Эффекты и отсутствующие состояния относятся к P-04, а фактическая browser/визуальная проверка отложена по PROMPT-013.

## D-13 — Доступные эффекты P-04 без выдуманного контента

14.10.2026, PROMPT-014/015. После приемки P-03 и коммита daff15a работа продолжена тем же gpt-6-sol/high. Доступны исходная фраза строки, три призовые карточки, финальная геометрия desktop (y80/150/220, шаг70) и палитра. Выбраны CSS keyframes для строки, local CSS sticky для призов и простые demo hover/focus/active для кнопок; без новых библиотек и общего animation engine. При необходимости реальные высоты карточек измеряются ResizeObserver, чтобы длинные тексты и низкий viewport оставались читаемыми.

Альтернативы: ждать всей P-02 — останавливает независимые эффекты; фиктивные Q2/Q3 или три копии Q1 — не выполняют ТЗ и запрещены; новая animation-библиотека — лишняя зависимость для простых эффектов. Единственный Q1 остается статичным, раскрытый mobile menu не создается без доступного контекста.

Параметры скорости/направления строки, sticky offset и demo-интерактив — инженерные решения в рамках разрешенного P-04, не точная реконструкция Figma Motion или Hover/Pressed. Подтвержденные статические измерения отделяются от этих решений в отчете исполнителя и независимой проверке. Сам skill figma-implement-motion рекомендует получение Motion, но прямой запрет пользователя на новые MCP имеет приоритет; точные Motion не заявляются воспроизведенными.

Браузерное ограничение сохраняется: origin ранее отклонен, пользователь разрешил продолжение без браузера. Не открываем его повторно и не используем обходы. Проверка доступных lifecycle/расчетов и сборки не заменяет визуальную проверку, которую пользователь выполнит в составе единой приемки P-04.

D-13, результат проверки 14.10.2026: реализованы CSS-строка и sticky, generic demo состояния. Выбраны 48 px/s, desktop top80/step70, mobile top16/step48, bottom gap16, runway 260; transition160ms, hover−2px, active+1px/scale0.94. Они описаны отдельно от Figma-фактов. В независимом просмотре расчет числа копий и ограничение sticky-top исправлены для короткой строки/низкого окна и разных высот; reverse pass выбран вместо общего максимума высоты, чтобы высокая первая карточка не уводила короткие последующие за экран. Методы проверены реальными вызовами с синтетическими измерениями, не DOM-рендером.

## D-14 — Hero по Да/Нет и явное отсутствие двух фото

Актуализация PROMPT-018: пользователь предоставил два PNG, первый для Q2, второй для Q3. Временное отсутствие фото заменяется реальными изображениями. Их сохраняем побайтно в public/assets/hero-user/ и подключаем через JSON; происхождение отдельно от 350 экспортов Figma. Пропорции/альфа сохраняются; допустимы только локальные CSS-настройки размещения новых портретов без изменения Q1 или обработки пикселей. Новых библиотек и image generation не нужно. Полная P-02 все еще имеет другие пробелы.

## D-16 — Внешние шаблоны и локальные стили компонентов

14.10.2026, PROMPT-021. Пользователь указал, что inline-шаблоны в TS и единый секционный CSS затрудняют чтение проекта.

Выбор: все девять визуальных Angular-компонентов используют соседние `.component.ts`, `.component.html` и `.component.css` через `templateUrl`/`styleUrl`. В TS остаются metadata, inputs, signals и lifecycle. Стили header, hero, prizes, leaderboard, mechanics, final CTA, footer, Button и состояний страницы находятся рядом с соответствующим компонентом. Глобальными остаются только reset, контейнер, общая eyebrow/фокус-основа и общий brand header/footer; токены остаются отдельными.

Почему: человек сразу видит разметку, поведение и оформление выбранного блока, а изменения одной секции не требуют поиска в трехсотстрочном глобальном файле. Границы компонентов, JSON и поведение не меняются.

Альтернативы: только вынести HTML, оставив все секционные стили глобальными, формально создало бы CSS-файлы без ясной ответственности. Создавать новые подпапки, дополнительные компоненты или CSS-слой ради рефакторинга не нужно. Изоляция Angular потребовала перенести состояния host общей кнопки на `:host`/`:host-context`; это сохраняет варианты header/hero/leaderboard и не добавляет JavaScript.

## D-17 — Отдельная папка каждого компонента раздела

14.10.2026, PROMPT-022. Пользователь уточнил D-16: плоский список из 21 файла в `src/app/quiz/` тоже неудобен для чтения.

Общие `quiz-content.ts` и `quiz-content.service.ts` остаются в корне `quiz/`, потому что их используют несколько секций. `app.component` остается в корне приложения, общая кнопка уже находится в `components/button/`.

Почему: дерево отражает границы компонентов, а инфраструктурные файлы не маскируются среди 21 секционного файла. Изменились только пути и относительные импорты; классы, selectors, шаблоны, стили и runtime-поведение сохранены.

Альтернативы: единая папка `quiz/components/` добавила бы лишний промежуточный уровень без новой границы; перенос типов и сервиса в папку отдельного компонента создал бы неверную зависимость. Историческое решение D-16 сохранить плоские файлы уточнено прямым запросом пользователя.

## D-19 — Публикация Angular на GitHub Pages в подпути репозитория

15.10.2026, PROMPT-025. GitHub Pages запускал Jekyll workflow в корне Angular-репозитория, поэтому приложение не попадало в Pages artifact.

Выбор: заменить единственный workflow на Node 22, `npm ci`, production-сборку с `--base-href /quiz/`, upload artifact каталога `dist/quiz-demo/browser/` и deploy-pages. CSS background URL направить на `/quiz/assets/...`: обычные абсолютные `/assets/...` обходили бы базовый путь `/quiz/`, а Angular не собирает asset paths вида `assets/...` из публичной папки при обработке компонентного CSS.

Почему: Pages обслуживает проектный сайт из подпути `/quiz/`; base href направляет Angular-загрузчику `mocks/quiz.json` и изображениям в HTML в этот каталог, а явный префикс CSS-фонов гарантирует тот же путь. Artifact содержит готовый `index.html` в корне и runtime assets рядом.

Альтернативы: Jekyll либо второй Pages workflow сохраняли бы конкурирующую/неверную публикацию. Деплой корневого сайта без base href обращался бы к `/assets` и `/mocks` вместо `/quiz/assets` и `/quiz/mocks`. Конфигурация остается простой, без дополнительных зависимостей. После первой неудачной локальной сборки относительные пути CSS заменены на абсолютные в пределах `/quiz`; точная production-команда и проверка путей в artifact прошли.
