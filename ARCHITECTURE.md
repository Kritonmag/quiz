# Архитектура страницы Quiz

Статус: доступный P-03 принят по PROMPT-014 и сохранен в daff15a; доступный P-04 с PNG Q2/Q3 принят пользователем по PROMPT-019. Доработки структуры P-05 по PROMPT-021/022 выполнены и ожидают ручной проверки. Основание: SPEC v1.0, решения D-01…D-17. Дата: 2026-10-14. Временный Arial согласован по PROMPT-012.

Частичный разбор P-02: [исходные данные](docs/figma/p02/REPORT.md) и [проверка главного агента](docs/reviews/P-02.md). Ассеты находятся в `public/assets/figma/`, привязки — в `docs/figma/p02/assets-manifest.json`. P-03 реализует сохраненную доступную статическую страницу. Анимации относятся к P-04; breakpoints и max-width на 8К — инженерные решения, а не Figma-факты. Новые MCP-запросы запрещены, недоступные состояния не выдумываются.

## Структура

Одно Angular-приложение с одной страницей и standalone-компонентами по визуальным разделам. Корневой компонент загружает данные, показывает loading/error и собирает страницу. Дополнительный роутер, глобальное хранилище и backend пока не нужны.

Текущая структура: каждый визуальный компонент состоит из соседних `.component.ts`, `.component.html` и `.component.css`. Каждый компонент раздела дополнительно находится в собственной папке внутри `src/app/quiz/`. TypeScript содержит metadata и поведение, HTML — только шаблон, CSS — локальные стили секции. `src/styles.css` хранит reset, контейнер, общую типографику и оформление бренда, используемое в header/footer; токены остаются в `src/styles/tokens.css`.

```text
public/
  mocks/quiz.json                  # контент всех семи разделов
  assets/figma/                    # оригиналы из P-02
src/
  main.ts                          # bootstrap, HttpClient, zoneless provider
  index.html
  app/
    app.component.{ts,html,css}    # загрузка, состояния и сборка страницы
    components/button/
      button.component.{ts,html,css} # общие CTA
    quiz/
      quiz-content.service.ts      # HTTP mocks/quiz.json
      quiz-content.ts              # интерфейсы и проверка входных данных
      header/header.component.{ts,html,css}
      hero/hero.component.{ts,html,css}
      prizes/prizes.component.{ts,html,css}
      leaderboard/leaderboard.component.{ts,html,css}
      mechanics/mechanics.component.{ts,html,css}
      final-cta/final-cta.component.{ts,html,css}
      footer/footer.component.{ts,html,css}
  styles/tokens.css
  styles.css                       # только общие глобальные стили
```

Автотаймер hero не требуется уточнением PROMPT-016: вопросы меняются по Да/Нет. PNG Q2/Q3 получены от пользователя по PROMPT-018; их точное размещение требует визуальной проверки.

Внутреннюю hero-карточку выделять в компонент только при достаточной сложности шаблона. Повторяющаяся кнопка сразу выделяется в общий компонент `src/app/components/button/`. Не заводить универсальные компоненты на каждую надпись или контейнер.

### Общие компоненты приложения

`src/app/components/` — общая папка для переиспользуемых UI-компонентов. Первый компонент — `ButtonComponent`: его используют header, hero, призы, рейтинг и финальный CTA. Каждый новый общий компонент получает собственную подпапку; дополнительные компоненты добавляются по реальной потребности при изменении функционала. Компоненты разделов страницы пока остаются в `quiz/`.

Кнопка — простой standalone-компонент с нативным `<button type="button">` внутри. Подпись передается из мок-данных через шаблон родителя; цветовой вариант задается простым входным параметром, адаптивные размеры — CSS. Общие hover/focus-visible/active и варианты внешнего вида Figma реализуются один раз в стилях кнопки с использованием токенов. Не включать в кнопку HTTP-запросы, навигацию или игровую логику; бизнес-действия в этой демонстрации отсутствуют.

Компоненты страницы импортируют кнопку там, где используют ее. Общая кнопка не зависит от `quiz/` и загрузчика моков: направление зависимости — от секций к общим компонентам. Не нужны общий базовый класс, реестр компонентов или автоматическая глобальная регистрация. Обычные текстовые ссылки остаются ссылками с отключенным переходом в демо.

Standalone-компоненты поддерживаются Angular и рекомендованы для нового кода: [официальное руководство](https://angular.dev/guide/ngmodules/overview). `public/` предназначен для статических ресурсов, копируемых при сборке: [структура проекта Angular](https://angular.dev/reference/configs/file-structure).

## Данные

`quiz-content.service.ts` один раз получает JSON по относительному URL `mocks/quiz.json` через Angular HttpClient. Все мок-данные проекта хранятся отдельно в `public/mocks/`, изображения и шрифты — в `public/assets/`. Страница держит локальные состояния загрузки/ошибки/готовности и передает нужные данные компонентам. Для выбранной версии проверить настройку HttpClient; не переносить без проверки настройки более нового Angular в Angular 20: [официальная настройка HttpClient](https://angular.dev/guide/http/setup).

Реализованные разделы JSON P-03:

| Ключ | Содержимое |
| --- | --- |
| `header` | Название бренда, alt, пункты меню с URL, подпись CTA |
| `hero` | Заголовок, описание, CTA, ribbon и ribbonSpeedPxPerSecond, массив questions с id/текстом/nullable фото и alt/подписями |
| `prizes` | Заголовки, описание, правила, карточки, CTA и sticky-параметры desktop/mobile/top/step/gap/runway |
| `leaderboard` | Заголовки, список игроков с местом/именем/баллами, CTA |
| `mechanics` | Заголовки, числа, подписи и объяснения |
| `finalCta` | Заголовок, описание, alt иллюстрации, CTA |
| `footer` | Название, описание, организатор, поддержка, copyright, юридические ссылки |

Из JSON рендерить текст обычной интерполяцией; не использовать произвольный HTML или исполняемые строки. TypeScript-интерфейс сам не проверяет входной JSON: добавить простую проверку обязательных полей, массивов без библиотеки схем; длительности добавить вместе с поведением P-04. Проверка должна принимать корректный контент и показывать ошибку для неверного, не скрывая ее жестко зашитыми маркетинговыми текстами.

В P-05 существующая проверка `localAsset()` объединяет условия для всех изображений JSON: локальные папки `assets/figma/` / `assets/hero-user/`, отсутствие `..` и расширение PNG/JPEG/WebP/SVG. Наличие конкретного файла проверяется при приемке ресурсов, а не по одному расширению. Отдельная проверка расширения в hero удалена; структура компонентов и поток данных сохранены.

Все управляемые тексты и URL находятся в JSON. Техническая разметка, поведение и CSS-токены остаются в коде; замена дизайна не обещана без сборки. Данные рейтинга показываются как задано в файле, без реализации игрового расчета. Структурные id используются для `track`, чтобы автосмена не пересоздавала всю страницу.

**Условие обновления без сборки:** исходный `public/mocks/quiz.json` копируется при build. После публикации меняется именно статический файл `mocks/quiz.json` в опубликованной папке либо отдельно обслуживаемый ресурс по тому же URL. Для этого ресурса настроить revalidation/Cache-Control и при необходимости сброс кеша CDN; страницу перезагрузить. Изменение только исходного файла на машине разработчика не обновляет уже опубликованную страницу. Поллинг и CMS в текущую задачу не входят.

### Мок-данные в составе этапа P-03

Моки, загрузчик, типы, токены и компоненты включены в **P-03 «Готовая адаптивная страница»**. Подготовку всего набора мок-данных можно поручить одному субагенту внутри этапа, сохранив область `public/mocks/`, но не выделять для этого отдельный этап и приемку. Исполнители компонентов заранее не назначаются; главный агент отвечает за целую страницу и интеграцию.

- После разбора Figma в P-02 подготовить `quiz.json` для всех семи разделов из таблицы выше: меню, заголовки, тексты, CTA и ссылки, подтвержденный hero Q1 (другие варианты ждут P-02), три приза, топ-10 и демонстрационные результаты, механика, финальный CTA и footer.
- Использовать подтвержденные тексты и значения макета, стабильные уникальные id и пути к ассетам из P-02. Сохранить заглушки неизвестных контактов и юридических данных; не придумывать реальные реквизиты.
- Согласовать структуру полей с главным агентом по таблице выше до подключения компонентов. Один JSON — исходный простой вариант; разделять его на несколько файлов внутри `public/mocks/` только при реальной необходимости, обновив загрузчик и документацию.
- Проверить синтаксис JSON, полноту секций, обязательных полей и уникальность id внутри списков. Не импортировать мок-данные в TypeScript и не создавать сервер моков.
- Главный агент проверяет данные по Figma и SPEC и их загрузку в странице. Пользователь проверяет их в составе законченного P-03; самостоятельной приемки каждого JSON или компонента нет.

«Весь проект» означает демонстрационную страницу в пределах SPEC. Создание настоящей игры, алгоритма начисления баллов и полного банка из 100 игровых вопросов в эту задачу не входит.

## Раскладка и стили

- В P-03 базовые desktop-правила и mobile media queries, Grid/Flex для секций; промежуточные точки перелома являются инженерными решениями.
- Основной desktop-фрейм — 1440 px, mobile — 375 px. Поля подтвержденных секций есть в design-facts P-02 (например, desktop-призы: x=80/560, mobile-столбец: x=16); не назначать одно поле всем блокам. Текущая ширина Homepage 8148 px не является viewport.
- Для 8К ограничить ширину содержимого CSS-переменной и центрировать. Фоны занимают весь viewport. Не использовать `transform: scale()` для масштабирования страницы.
- Токены: цвета, spacing, радиусы, шрифты и размеры, контейнеры, transition durations, z-index; имена по назначению. Точные значения извлечь из Figma, не выдумывать сейчас.
- Не задавать фиксированные высоты длинным текстовым блокам. Декоративный overflow ограничивать локально, чтобы не ломать `position: sticky` у призов.

## Поведение секций

| Секция | Локальное состояние / реализация |
| --- | --- |
| Header | Исходная кнопка с demo-интерактивом; панель Open отложена до ее context/PNG |
| Hero | Signal-индекс, computed вопрос; обе кнопки переключают questions по кругу вместе с PNG. Q1 — исходный Figma-ассет, Q2/Q3 — пользовательские PNG; aria-live для текста |
| Бегущая строка | Две одинаковые группы; число копий по измеренной ширине, CSS keyframes, скорость JSON. Один доступный текст; reduced-motion/hidden/hover/focus. ResizeObserver/listener cleanup и guard microtask после destroy |
| Призы | CSS sticky, возрастающий z-index. Top по высоте карточек/viewport, обратный проход сохраняет шаг; ResizeObserver/resize/orientation с cleanup. Scroll-listener не нужен. Параметры инженерные, не авторитетные Motion |
| Рейтинг / механика / footer | Отображение JSON; локальное состояние не требуется |
| Все повторяющиеся CTA | Общий ButtonComponent из `components/button/`, единые hover/focus-visible/active; бизнес-действия отсутствуют |
| Текстовые ссылки | CSS hover/focus-visible/active; переходы в демо отключены |

Расчеты sticky-карточек проверены с синтетическими измерениями низкого viewport и mobile; реальный CSS-рендер не проверен. Если карточка выше доступной области, ее содержимое должно читаться в обычном потоке до перекрытия; окончательная техника определяется проверкой. Не рассчитывать скролл всех блоков в общем сервисе.

## Проверки архитектуры

Сборка и проверка типов; успешная и неуспешная загрузка JSON; замена опубликованного JSON без сборки; ручная сверка 375/1440; матрица адаптивности; hero/бегущая строка/sticky; reduced-motion; клавиатура; отсутствие действий CTA. План конкретных проверок ведется в `DEVELOPMENT_PLAN.md`. Новые автотесты сначала предложить пользователю с назначением, как требует AGENTS.md.

Текущие инженерные параметры P-04 и границы JSON описаны в docs/implementation/p04/content-provenance.json. Скорость 48 px/s, desktop 80/70 и mobile 16/48 px, runway 260 px не выдаются за прототип Figma. Фактические проверки и оставшиеся материалы — docs/reviews/p04/REPORT.md.

Доработка PROMPT-016/017: hero.question заменен на hero.questions. Обе кнопки переключают один локальный индекс по кругу, computed выбирает вопрос. Q1 использует исходный PNG; Q2/Q3 временно с null image/imageAlt по явному разрешению пользователя. Новые референсы — docs/references/hero/, оригиналы отсутствующих фото все еще нужны. Это замена прежнего статичного Q1, без автоинтервала, расчета баллов и игровых запросов.
