```text
Ранний просмотр: 1) строка сейчас всегда 2 фразы на группу. При изменении ribbon в JSON на короткий текст (или viewport736 на tablet) группа может быть уже ленты: нужен расчет количества одинаковых копий по ширине viewport/фразы, а не только скорости. 2) top=min(base+i*step, viewport-cardHeight-gap) дает одинаковые top для трех одинаково высоких mobile-карточек при низком окне, шаг полностью теряется; проверь желаемый порядок/читабельность, можно общий безопасный base по максимальной высоте с учетом последних смещений. 3) удаление overflow:hidden у .prizes открывает псевдоэлемент шириной432 на viewport375? Запиши точные границы скорости10..300 и sticky в provenance — это инженерная валидация, не Figma значения.
```

```text
Уточнение к sticky: простой общий max-height может увести все короткие карточки за экран, если только первая очень длинная. Полезно ограничить top каждого по viewport-height-gap и пройти от последней к первой, дополнительно top[i] <= top[i+1]-step. Это сохраняет возрастающий порядок и безопасный низ каждой карточки при разных высотах. В стандартном desktop800/480 ожидаем80/150/220, в low-mobile равных высоких карточек сохраняется шаг, а не три одинаковых top. Если выберешь иной простой расчет с этими свойствами — подойдет.
```
