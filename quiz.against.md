# Правила агента Quiz

Обновлено: 2026-10-13, Europe/Moscow. Имя `quiz.against.md` сохранено по запросу пользователя.

## Начало задачи и сохранение контекста

1. Прочитай `AGENTS.md`, этот файл, `SPEC.md`, актуальный план и решения по затронутой части.
2. Подтверди: **«AGENTS.md учтен. quiz агент MD учтён.»**
3. Запиши входной пользовательский промпт в `prompts.md` до выполнения основной работы. Журнал содержит только реестр, тексты промптов пользователя и шаблон следующей записи. Задания главного агента, субагентов и инструментов туда не записывай. Если журнал еще не существует, создай его первой правкой.
4. Обнови статус задачи в `DEVELOPMENT_PLAN.md`. Укажи границы, критерий готовности и исполнителя.
5. Изучи релевантные файлы и существующие паттерны до изменения кода.

## Главный агент и субагенты

- Главный агент отвечает за целостность страницы, архитектуру, интеграцию, журнал и актуальность плана.
- Эти правила описывают порядок делегирования, но сами по себе не являются поручением запускать субагентов. Запускай их при явном поручении пользователя или применимых инструкциях.
- Перед передачей задачи укажи исполнителя в плане. Передай ссылки на правила, SPEC, пункт плана, границы файлов и критерии приемки. Задание агента в `prompts.md` не записывай.
- Не назначай одновременно нескольким агентам правки одних и тех же файлов. Субагент возвращает список изменений, проверок, ограничений и нерешенных вопросов.
- Субагент не принимает собственный результат. После его отчета главный агент читает изменения, проверяет соответствие SPEC, интеграцию и запускает подходящие существующие тесты и проверки. При необходимости новых тестов сначала объясняет их назначение пользователю.
- Главный агент проверяет каждый результат субагента и его интеграцию в законченный этап. После этой проверки этап получает статус `ожидает ручной проверки`; пользователь проверяет целый этап, включая результаты субагентов. Отдельного исполнителя и отдельной приемки для каждой кнопки или секции не создавать. Только явная приемка пользователя переводит этап в `готово`.
- Если пользователь нашел замечания, статус становится `на доработке`; исправления и повторные проверки фиксируются в плане и `ai_noted.md`.

## Простой код

Angular 20+, компоненты по разделам страницы, локальное состояние. CSS для раскладки и простых эффектов. Дополнительный JavaScript только там, где он нужен для поведения. Production-зависимости сверх согласованного Angular-стека требуют отдельного согласования.

Общие переиспользуемые UI-компоненты размещай в `src/app/components/`, каждый в собственной подпапке. Повторяющиеся CTA используют общий компонент `button/`. Другие общие компоненты добавляй по реальной необходимости; компоненты разделов страницы остаются в `quiz/`. Общие компоненты не зависят от конкретных секций и загрузчика контента.

Не создавай заранее общий движок анимаций, CMS, state-management слой, универсальный renderer секций или настоящую игру. Масштабируй архитектуру только после конкретной необходимости и запиши причины в `ai_decisions.md`.

## Ведение документов

| Документ | Когда обновлять |
| --- | --- |
| `prompts.md` | Только промпты пользователя, включая его уточнения и повторные задания; реестр с временем записи, моделью и степенью рассуждения |
| `ai_decisions.md` | Архитектурный выбор, альтернативы, изменение ранее выбранного подхода |
| `ai_noted.md` | Наблюдения, предположения, риски, замечания пользователя, фактические исправления и результаты проверок |
| `SPEC.md` | Изменение требований и критериев приемки |
| `ARCHITECTURE.md` | Изменение структуры, границ компонентов или потоков данных |
| `DEVELOPMENT_PLAN.md` | Начало работы, прогресс, блокировка, проверка, доработка, ручная приемка |

Сохраняй историю: не удаляй старые промпты, решения и замечания. Связывай записи с идентификаторами промптов и задач. Не выдавай предложение AI за одобрение пользователя. Отмечай, что удалось с первого раза, только по фактической проверке; пользовательскую приемку фиксируй отдельно.

Время записи в `prompts.md` указывай в читаемом формате `ДД.ММ.ГГГГ, ЧЧ:ММ:СС`, по Москве (МСК, Europe/Moscow). Не подменяй время записи неизвестным временем получения старого сообщения. Модель и уровень рассуждения записывай из доступных метаданных или явного уточнения пользователя; если они неизвестны, пиши `не предоставлено сессией`. Для PROMPT-001…PROMPT-006 пользователь подтвердил GPT-6.1 Solo и высокую степень рассуждения. Не восстанавливай метаданные догадками и не сохраняй скрытые рассуждения модели.

## Коммиты

Все сообщения коммитов в этом проекте пиши только на русском языке: и заголовок, и описание, если оно есть. Перед коммитом проверь состав изменений и не включай локальные настройки IDE или случайные файлы.

## Завершение задачи

Просмотри diff, выполни минимальные необходимые проверки, внеси реальные результаты в план. Без Git проверь перечень созданных файлов и их содержимое, явно указав ограничение. Для результатов субагентов подготовь понятный маршрут ручной проверки пользователя. В финале сообщи изменения, проверки и ограничения. Не отмечай работу завершенной по одному отчету исполнителя.
